# ADB2WiFi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a menu-bar-only native macOS utility that lists physical Android devices and establishes verified Wi-Fi ADB from USB with one click.

**Architecture:** A Swift 6 package with a testable `ADB2WiFiCore` library (ADB process client, device store, connection coordinator) and an `ADB2WiFi` executable (NSStatusItem + NSPopover + SwiftUI). A packaging script wraps the release binary in an `LSUIElement` `.app`. No Dock icon, no main window, no bundled ADB.

**Tech Stack:** Swift 6, SwiftUI, AppKit (`NSStatusItem`/`NSPopover`), Foundation `Process`, Observation, Swift Testing, macOS 14+, Command Line Tools only (no Xcode.app required).

**Spec:** `docs/superpowers/specs/2026-09-11-adb2wifi-design.md` (write this file in Task 1 from the approved product spec in the user request). Android USB-to-Wi-Fi workflow: https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi (the “after an initial USB connection” `tcpip 5555` path; QR/code pairing is deferred).

## Global Constraints

- App name: `ADB2WiFi`. English UI only.
- Bundle identifier: `io.github.mariocodarin.ADB2WiFi`.
- macOS 14+ (`platforms: [.macOS(.v14)]`). Swift language mode 6.
- Existing ADB only. Never bundle, download, or auto-install ADB. Never run `adb kill-server` / `adb start-server` as a recovery strategy.
- V1 is USB-initiated Wi-Fi ADB only. No QR/code pairing, auto-reconnect, launch-at-login, mirroring, or file transfer.
- Hide emulators. Merge transports by verified serial identity (`ro.serialno`), never by model name.
- Closing the popover must not cancel in-flight connection work. Quit must leave established ADB connections intact.
- Hardware validation on a real phone is explicitly pending and must be labeled as such in the README; do not claim it passed.
- Save design + this plan under `docs/superpowers/` during implementation.
- This Mac’s ADB is `/opt/homebrew/bin/adb` (v37.0.1). Discovery must still try override → Homebrew → Android SDK paths.
- Toolchain: Apple Swift 6.3.3 + Command Line Tools SDK at `/Library/Developer/CommandLineTools`. Use `swift build` / `swift test`, not `xcodebuild`.

```swift
public struct DeviceIdentity: Hashable, Sendable {
    public var serialNo: String
    public var shortSerial: String {
        serialNo.count > 8 ? String(serialNo.suffix(8)) : serialNo
    }
    public init(serialNo: String) { self.serialNo = serialNo }
}

public enum TransportKind: String, Sendable { case usb, network }

public enum Availability: String, Sendable {
    case device, unauthorized, offline, unknown
}

public enum ConnectionStep: String, Sendable {
    case findingAddress, enablingWifi, connecting, verifying
}

public enum OperationState: Equatable, Sendable {
    case idle
    case connecting(ConnectionStep)
    case awaitingAddress(suggested: String?)
    case readyToUnplug
    case failed(AppError)
}

public struct Transport: Equatable, Sendable {
    public var serial: String
    public var state: Availability
    public var verified: Bool
    public init(serial: String, state: Availability, verified: Bool = false) {
        self.serial = serial
        self.state = state
        self.verified = verified
    }
}

public struct Device: Identifiable, Equatable, Sendable {
    public var id: DeviceIdentity { identity }
    public var identity: DeviceIdentity
    public var model: String
    public var usb: Transport?
    public var network: Transport?
    public var operation: OperationState
    public var isWiFiConnected: Bool { network?.verified == true && network?.state == .device }
    public init(identity: DeviceIdentity, model: String, usb: Transport? = nil,
                network: Transport? = nil, operation: OperationState = .idle) {
        self.identity = identity
        self.model = model
        self.usb = usb
        self.network = network
        self.operation = operation
    }
}

public enum AppError: Equatable, Error, Sendable {
    case missingADB
    case authorizationPending
    case deviceOffline
    case missingWiFiAddress
    case unreachableEndpoint
    case usbRemoved
    case timeout
    case identityMismatch
    case adbOutput(String)
    public var guidance: String { /* concise per-case copy; see Task 8 for final strings */ "" }
}

public struct ADBTransport: Equatable, Sendable {
    public var serial: String
    public var state: Availability
    public var product: String?
    public var model: String?
    public var usb: String?
    public var transportID: String?
    public var isEmulator: Bool { serial.hasPrefix("emulator-") }
    public var isNetwork: Bool {
        serial.contains(":") || serial.contains("._adb-tls-connect._tcp")
    }
    public init(serial: String, state: Availability, product: String? = nil,
                model: String? = nil, usb: String? = nil, transportID: String? = nil) {
        self.serial = serial; self.state = state; self.product = product
        self.model = model; self.usb = usb; self.transportID = transportID
    }
}
```

`ProcessCommandRunner` must:
- Launch `Process` with the given executable and arguments (never `/bin/sh -c`).
- Capture stdout/stderr pipes.
- Enforce timeout via `Task` + `process.terminate()` (SIGTERM). Do not send SIGKILL to `adb` as a first step; if it does not exit within 1s after terminate, then `process.interrupt()`.
- Throw `ADBError.timeout` on timeout.
- Never invoke `adb kill-server`.

### Task 6: Connection coordinator — happy path, retries, verification

**Files:**

    - `func disconnect(identity: DeviceIdentity) async`

Happy path (must follow Android’s USB-to-Wi-Fi steps):

1. Snapshot the authorized USB transport. If missing → `.usbRemoved`. If unauthorized → `.authorizationPending`. If a connect is already running for this identity, return immediately.
2. Set `.connecting(.findingAddress)`. Shell `ip -o -4 addr show up` on the **USB serial**. If no unambiguous IPv4 and no `manualAddress`, set `.awaitingAddress(suggested:)` and return **before** `tcpip`.
3. Set `.connecting(.enablingWifi)`. `adb -s <usbSerial> tcpip 5555`. Preserve the card if USB disappears (ADB restart).
4. Set `.connecting(.connecting)`. Retry `adb connect <ipv4>:5555` until success or a **20-second overall deadline** from the start of step 4. Parse stdout; `failed to connect` is not success.
5. Set `.connecting(.verifying)`. `adb -s <ipv4>:5555 shell getprop ro.serialno` must equal the captured `DeviceIdentity.serialNo`. Also require a non-empty shell response (the getprop is the verification command).
6. Mark `network.verified = true`, `operation = .readyToUnplug`. Only then is the device “Wi-Fi connected”.
